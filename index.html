3. คลาส BinaryTree

คลาสแม่ของ CBT และ BST ใช้ DefaultMutableTreeNode ของ Swing เป็นโหนด โดยตกลงกันว่า ลูกคนที่ index 0 = ซ้าย, index 1 = ขวา ข้อมูลที่โหนดเก็บ (getUserObject()) คือ Product

3.1 ตัวแปรและเมธอดพื้นฐาน

สมาชิกทำอะไร
protected rootโหนดราก ตอนเริ่มเป็น null (ต้นไม้ว่าง) คลาสลูกเข้าถึงได้เพราะเป็น protected
getRoot()คืนค่าโหนดราก
isRealNode(node)เช็คว่าเป็นโหนดจริง คือ ไม่ใช่ null, เก็บ Product และไม่ใช่โหนดว่าง (id ≠ "0") ใช้กันไม่ให้นับ/เทียบโหนด dummy ของ BST

3.2 getHeight() — ความสูงของต้นไม้

int height = 0;
Queue<DefaultMutableTreeNode> level = new LinkedList<>();
level.add(root);
while (!level.isEmpty()) {
    height++;                       // เจอ 1 ระดับใหม่
    int size = level.size();        // จำนวนโหนดในระดับนี้
    for (int i = 0; i < size; i++) {
        node = level.poll();
        for each child that isRealNode: level.add(child);
    }
}
return height;

แนวคิด: นับทีละระดับ (level by level) ใช้คิวเก็บโหนดของระดับปัจจุบัน ทุกครั้งที่ประมวลผลครบทั้งระดับ ก็บวกความสูง 1 แล้วไประดับถัดไป

  • นับเป็น จำนวนระดับ: ต้นไม้ที่มีแต่ราก = 1, ต้นไม้ว่าง = 0
  • โหนด dummy ของ BST ไม่ถูกนับ (เพราะกรองด้วย isRealNode)
  • เขียนแบบวนลูป (iterative) ไม่ใช้ recursion เพื่อไม่ให้ stack เต็มเมื่อต้นไม้ลึก

ค่าที่เห็นเมื่อรัน: ข้อมูล 100,000 ชิ้น → CBT สูง 17 (เพราะ 216 = 65,536 < 100,000 ≤ 217) และ BST สูงประมาณ 40–45 (BST สุ่มไม่สมดุลเท่า CBT)

3.3 depthFirstSearch(key) — ค้นแบบลึกก่อน (DFS)

private DefaultMutableTreeNode depthFirstSearchRecursive(node, key) {
    if (node == null) return null;                  // 1) ไม่มีโหนด
    if (isRealNode(node) && name.equals(key)) return node;  // 2) เจอแล้ว
    if (node.getChildCount() > 0) {                 // 3) ลองฝั่งซ้ายก่อน
        found = depthFirstSearchRecursive(child 0, key);
        if (found != null) return found;
    }
    if (node.getChildCount() > 1) {                 // 4) ถ้ายังไม่เจอ ลองฝั่งขวา
        found = depthFirstSearchRecursive(child 1, key);
        if (found != null) return found;
    }
    return null;                                    // 5) ไม่มีใน subtree นี้
}

แนวคิด: เจาะลงทางซ้ายให้สุดก่อน ถ้าไม่เจอค่อยถอยกลับมาลองทางขวา (ใช้ recursion — ตัวเมธอดเรียกตัวเอง) ถ้าเจอที่ฝั่งซ้ายจะ “ลัดวงจร” คืนค่าทันทีโดยไม่ต้องดูฝั่งขวา

  • depthFirstSearch (public) เป็นตัวห่อ เรียก depthFirstSearchRecursive(root, key)
  • เทียบด้วย getName().equals(key) — ใช้ name เป็นกุญแจค้นหา
  • เวลาที่ใช้: O(n) กรณีแย่สุดต้องเดินทุกโหนด

3.4 breadthFirstSearch(key) — ค้นแบบกว้างก่อน (BFS)

queue.add(root);
while (!queue.isEmpty()) {
    current = queue.poll();                     // หยิบหัวคิว
    if (isRealNode(current) && name.equals(key)) return current;
    if (childCount > 0) queue.add(child 0);     // ซ้ายเข้าคิว
    if (childCount > 1) queue.add(child 1);     // ขวาเข้าคิว
}
return null;

แนวคิด: ค้นทีละระดับจากบนลงล่าง: ราก → ลูกระดับ 1 → ลูกระดับ 2 … ใช้ คิว (เข้าก่อนออกก่อน) ทำให้โหนดที่อยู่ระดับตื้นกว่าถูกตรวจก่อนเสมอ เวลาที่ใช้ O(n) เช่นกัน

ต่างจาก DFS อย่างไร? DFS ใช้ stack (ผ่าน recursion) ดำดิ่งลงล่างก่อน ส่วน BFS ใช้ queue ไล่ทีละระดับ ทั้งคู่เจอคำตอบเดียวกัน แต่ลำดับการเดินผ่านโหนดต่างกัน จึงใช้เวลาไม่เท่ากันขึ้นกับว่าข้อมูลอยู่ตำแหน่งไหน

4. คลาส BST

ต้นไม้ค้นหาแบบทวิภาค: ที่ทุกโหนด “ฝั่งซ้ายต้องมีชื่อน้อยกว่า” และ “ฝั่งขวามีชื่อมากกว่าหรือเท่ากับ” (เรียงตาม name ผ่าน compareTo)

4.1 แนวคิดโหนดว่าง (dummy node)

BST ในโค้ดนี้ใช้กติกาพิเศษ: โหนดที่มีลูกต้องมีลูก 2 คนเสมอ ถ้าฝั่งใดยังไม่มีข้อมูล จะเอาโหนดว่าง (Product id = "0") ไปแทนที่ไว้ ทำให้ getChildAt(0) เป็นซ้ายและ getChildAt(1) เป็นขวาเสมอ ไม่สลับกัน

4.2 addNode(newNode) — เพิ่มโหนด

  1. ถ้า newNode หรือสินค้าข้างในเป็น null → ไม่ทำอะไร
  2. ถ้า root == null → โหนดนี้เป็นราก จบ
  3. ไม่เช่นนั้น เริ่มที่ p = root แล้ววนลูปลงไปหาที่ว่าง มี 2 กรณี:
กรณีการทำงาน
Case 1
p ไม่มีลูก (getChildCount()==0)		ถ้า newProduct < currProduct: ใส่ newNode เป็นลูกซ้าย และใส่ dummy เป็นลูกขวา
ถ้าไม่: ใส่ dummy เป็นลูกซ้าย และ newNode เป็นลูกขวา → แล้ว break
Case 2
p มีลูก 2 คน (==2)		เลือกซ้าย (ถ้า new < curr) หรือขวา (กรณีอื่น)
• ถ้าลูกฝั่งนั้นเป็น dummy → setUserObject(newProduct) ใส่สินค้าแทนที่ แล้ว break
• ถ้าเป็นโหนดจริง → p = ลูกนั้น แล้ววนต่อ

ตัวอย่าง: เพิ่ม M, F, T, A ตามลำดับ

M เป็นราก → F < M แต่ M ไม่มีลูก (Case 1) จึงได้ F ซ้าย + ∅ ขวา → T > M ขวาเป็น ∅ (Case 2) จึงแทนที่ด้วย T →
A < M ไปซ้ายเจอ F (โหนดจริง) ลงไปที่ F ซึ่งไม่มีลูก (Case 1) จึงได้ A ซ้าย + ∅ ขวา
ข้อสังเกต: ลูป while(true) ไม่ต้องจัดการกรณีมีลูก 1 คน เพราะโค้ดเพิ่มลูกทีละ 2 เสมอ ชื่อที่ เท่ากัน (compareTo == 0) จะถูกส่งไปทางขวา และโหนดที่ถูกแทนที่ dummy จะยังไม่มีลูกจนกว่าจะมีข้อมูลมาต่อใต้มัน

4.3 binarySearch(key) — ค้นแบบทวิภาค

p = root;
while (p != null) {
    curr = (Product) p.getUserObject();
    if (curr == null || curr.isEmpty()) return null;   // ชนที่ว่าง = ไม่มี
    int c = key.compareTo(curr.getName());
    if (c == 0)      return p;                          // เจอ
    else if (c < 0)  p = (childCount > 0) ? child 0 : null;   // ไปซ้าย
    else             p = (childCount > 1) ? child 1 : null;   // ไปขวา
}
return null;

แนวคิด: เปรียบ key กับชื่อที่โหนดปัจจุบัน ถ้าน้อยกว่าไปซ้าย มากกว่าไปขวา ตัดข้อมูลทิ้งครึ่งหนึ่งในแต่ละก้าว ไม่ต้องเดินทุกโหนด จึงใช้เวลาแค่ O(h) ตามความสูงต้นไม้ (~40 ก้าว จากข้อมูล 100,000 ชิ้น) เร็วกว่า DFS/BFS (O(n)) หลายร้อยเท่า

ใช้ได้เฉพาะ BST เพราะต้องอาศัยการเรียงลำดับ ใช้กับ CBT ไม่ได้เนื่องจาก CBT ไม่ได้เรียงตามชื่อ

5. คลาส CBT

Complete Binary Tree: เติมโหนดทีละระดับ จากซ้ายไปขวา ไม่เว้นช่อง ไม่สนใจค่าข้อมูล (ลำดับก่อน-หลังตามที่ใส่เข้าไป)

กลไก: nodeList + สูตรหาโหนดพ่อ

คลาสมี ArrayList nodeList เก็บโหนดทั้งหมดเรียงตามลำดับที่ใส่ แล้วใช้ index หาพ่อด้วยสูตร:

parentIdx = (currentIdx - 1) / 2      // หารจำนวนเต็ม (ปัดลง)
ตัวเลขในวงกลมคือ index ใน nodeList — พ่อของ 3 และ 4 คือ (3−1)/2 = (4−1)/2 = 1, พ่อของ 5 และ 6 คือ 2

addNode(newNode)

  1. ตรวจ null (เหมือน BST)
  2. เพิ่ม newNode ต่อท้าย nodeList
  3. ถ้ายังไม่มีราก → เป็นราก แล้วจบ
  4. ไม่เช่นนั้นคำนวณ currentIdx = nodeList.size() - 1 และ parentIdx ตามสูตร แล้ว parentNode.add(newNode)

เพราะลูกถูกเพิ่มตามลำดับ ลูกคนแรกของพ่อจึงเป็น index 0 (ซ้าย) และคนที่สองเป็น index 1 (ขวา) ตรงกับกติกาของ BinaryTree การเพิ่มแต่ละครั้งใช้เวลา O(1) จึงสร้างเร็วกว่า BST มาก (~0.02–0.05 วินาที เทียบกับ ~0.25 วินาที)

getSize() คืนจำนวนโหนดทั้งหมด (nodeList.size())

  • เวลาที่วัดได้เปลี่ยนไปในแต่ละครั้งที่รัน (ขึ้นกับเครื่อง, JIT ของ Java, และสินค้าที่สุ่มได้) การกด Report ซ้ำหลังค้นหาหลายรอบมักได้ค่าที่เสถียรกว่ารอบแรก
  • ถ้ากด Gen Product ใหม่ ต้องกด Gen Search Samples และ Gen CBT/BST ใหม่ทั้งหมด เพราะข้อมูลเก่าถูกล้างทิ้ง
